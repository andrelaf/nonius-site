Séries temporais densas, exatas até o nanossegundo em qualquer zoom.

Milhões de pontos num navegador, num programa de desktop ou nas imagens de um servidor, cada um no seu lugar por mais que você aproxime. Um único núcleo em Rust resume a série no servidor e a desenha na tela.

No crates.io e no npm; os pacotes .NET chegam em breve ao NuGet.

Por que o Nonius

Exato no zoom profundo

Um gráfico que guarda o tempo como float de 32 bits, como os gráficos em GPU costumam fazer, não distingue dois instantes de 2025 separados por menos de uns dois minutos. O Nonius guarda o tempo em nanossegundos de 64 bits até descontar o início da janela visível; só os pequenos deslocamentos que sobram viram floats.

Um núcleo, do servidor ao pixel

Os tiles e as imagens do servidor e o quadro do navegador saem do mesmo código Rust, compilado para WebAssembly na página. Uma página que monta a série a partir de tiles desenha o mesmo que uma página com a série inteira, e o PNG do servidor é o quadro do navegador.

Formato próprio, lido no lugar

Uma série viaja como NSB1: colunas little-endian alinhadas a 64 bytes, o layout dos buffers do Arrow. O navegador copia os bytes uma vez para a memória do gráfico e os lê ali mesmo: sem JSON, sem decodificador. Um feed ao vivo são quadros numerados num WebSocket, e um quadro perdido é recuperado.

Como funciona

Um ponto vai dos seus dados até a tela em cinco passos, e nenhum deles é uma conversão:

  1. O ponto: um tempo em nanossegundos, um valor e um peso, três inteiros de 64 bits, para que nada seja arredondado.
  2. NSB1: os pontos em colunas, cada uma começando num múltiplo de 64 bytes, lidas onde estão.
  3. A pirâmide: resumos em cada nível de zoom, e uma visualização lê o nível que cabe nos seus pixels.
  4. Tiles por HTTP: pedaços fixos em endereços que nunca mudam, guardados em cache por um ano.
  5. O feed ao vivo: quadros numerados, para que um quadro perdido seja notado e recuperado.

Como um ponto viaja, com os bytes de um tile de verdade.

Como se encaixa

O mesmo núcleo em Rust roda no seu servidor, na sua página e em programas nativos. Entre o servidor e a página passam só três coisas: tiles, um feed ao vivo e imagens.

Como usar

Um ponto é um tempo em nanossegundos, um valor e um peso. O valor é um inteiro com um número fixo de casas decimais, então 101.25 continua 101.25 dos seus dados até o quadro.

Seus dados: um CSV, sem código

nonius-server csv prices.csv prices.nsb

Vem com o cargo install nonius-server. Ele descobre as casas decimais, lê tempos em ISO 8601 e o ponto e vírgula e a vírgula decimal de uma planilha, e para na primeira linha que não consegue ler, dizendo qual. Depois, nonius-server prices.nsb serve o arquivo.

Rust: de um arquivo de série a uma imagem, sem GPU

cargo add nonius-format nonius-core
cargo add nonius-render --no-default-features

Leia o arquivo no lugar, guarde-o como uma pirâmide de resumos e desenhe qualquer visualização dele; aqui, a série inteira:

use nonius_core::{Loaded, Pyramid, Series, Width};
use nonius_format::{AlignedBytes, Container};
use nonius_render::{Still, Theme, still_png};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Read once into memory aligned for the columns, then read in place.
    let bytes = AlignedBytes::from_slice(&std::fs::read("day.nsb")?);
    let container = Container::parse_checked(bytes.as_slice())?;
    let series = Series::from_container(&container)?;

    // Summaries from one second up, nine levels (see nonius-core's
    // "Choosing the pyramid").
    let mut pyramid = Pyramid::new(Width::new(1_000_000_000)?, 9)?;
    pyramid.extend_sorted(series.iter())?;
    let loaded = Loaded::new(&pyramid, (series.t(), series.v(), series.w()));

    let (Some(&first), Some(&last)) = (series.t().first(), series.t().last()) else {
        return Err("the file holds no points".into());
    };
    // The image's size is in device pixels; `ratio` scales labels and lines.
    let png = still_png(&loaded, &Still {
        start: first,
        end: last + 1,
        width: 2400,
        height: 800,
        theme: Theme::light(),
        ratio: 2.0,
        scale: series.scale(),
        gap: None,
    })?;
    std::fs::write("day.png", png)?;
    Ok(())
}

O navegador: um gráfico que se arrasta e se amplia

npm install nonius
const chart = await createChart(canvas);

// Your points: times in nanoseconds since 1970 as BigInts, values as
// integers with a fixed number of decimal places (2 here: 10_000 is
// 100.00), and a weight each.
const { t, v, w } = randomWalk();
chart.setScale(2);
chart.push(t, v, w);

// Open on everything, the value axis fitted to it.
const [start, end] = [t[0], t[t.length - 1] + 1n];
const [lo, hi] = chart.autoscale(start, end, 0, 8);
chart.setView(start, end, lo, hi);

WebGPU quando o navegador tem, WebGL2 quando não tem, e um canvas 2D quando nenhum dos dois oferece um dispositivo. O pacote também acompanha os tiles de um servidor e recebe um feed ao vivo num worker; React e Vue o usam como qualquer outro módulo.

Um sensor que envia dados em rajadas aparece com uma reta de uma rajada à seguinte, a menos que você diga quanto tempo de pausa é uma lacuna: chart.setSeriesGap(id, ns) quebra a linha onde um ponto chega mais de ns nanossegundos depois do anterior, nos mesmos lugares em qualquer zoom.

.NET: o mesmo núcleo, em C#

dotnet add package Nonius
using var series = Series.FromNsb(File.ReadAllBytes(nsb));
if (!series.TryGetRange(out var first, out var last))
{
    throw new InvalidDataException($"{nsb} holds no points");
}
// Light, for a box of 1200 × 400 CSS pixels at a pixel ratio of 2:
// the size is in device pixels, the ratio in thousandths.
byte[] image = series.StillPng(new Still(first, last + 1, 2400, 800, Theme.Light, RatioPermille: 2000));
File.WriteAllBytes(png, image);

Nonius.Avalonia é um controle de gráfico para desktop, e Nonius.Blazor um componente que traz o pacote do navegador.

Especificações

O protocolo de rede foi escrito para ser implementado sem ler o código do Nonius: um cliente foi escrito só a partir dele, e suas colunas batem com as do núcleo. As especificações estão em inglês.

  • O protocolo (em inglês): um histórico em tiles por HTTP, e suas imagens.
  • O arquivo de pirâmide (em inglês): uma série e seus resumos, lidos no lugar.
